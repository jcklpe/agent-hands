# Excel text runs (experimental)
This Office.js adapter reads one named text cell and writes explicitly colored text runs through ExcelApi 1.18. The existing `scripts/excel` Graph CLI is unchanged. It never clears a cell, overwrites formulas, or uploads replacement workbook bytes. The color-writing command does not request strikethrough. The reference-repair command preserves existing character-level font properties, including strikethrough, through ExcelApi 1.18.

Run `node use-excel-workbooks/scripts/excel-live.mjs help` from the collection root. Requires the existing owned Office browser setup and Node dependencies supplied by `use-word-documents`, plus the Microsoft Files and setup CLIs. The current implementation is an experimental macOS integration; macOS host testing passed on one disposable cloud workbook: native text-run reads, a guarded write, independent download verification and preservation of the fixture's formula, table, legacy comment and hyperlink. This does not establish broader tenant or platform compatibility.

A runs file is a JSON array, for example `[{"text":"Original wording","font":{"color":"#C00000"}},{"text":" | Proposed wording","font":{"color":"#008000"}}]`. All text is literal. Only six-digit RGB colors are accepted. Maximum 128 runs and 32,767 UTF-16 code units. Select one ordinary, unmerged text cell by exact sheet name and A1 address. Numeric, formula, error, rich-data and merged cells refuse.

`configure` saves a manifest and opens only the owned Office browser for the selected workbook. Installing the add-in changes that workbook's add-in metadata and needs authorization for that target. The tool opens its installed ribbon command on each invocation; it does not enable persistent automatic startup. `preview` reads current text and formatting, compares saved text with a fresh download and stores an owner-only plan. `apply` requires that plan's hash, the file-write opt-in and authorization. It rechecks account, workbook and cell before dispatching once. `verify` downloads the saved workbook without replaying the edit. Inspect an uncertain operation before any further attempt.

Session readback does not establish persistence. Saved verification parses only downloaded XML; it does not write XML. It checks requested text and colors, not the entire workbook's fidelity. Unsupported color encodings fail verification rather than passing on text alone. Same-cell concurrent edits remain a race after the final check. Representative unchanged formulas, tables, comments and visuals require separate acceptance checks.

Tests: `node --test use-excel-workbooks/tests/*.test.mjs`. These use a simulated Office host and cover stale previews, target/API/read-only refusal, formula/non-text/merged refusal, bounded input, mixed-color readback and post-dispatch uncertainty. They do not prove a working tenant add-in deployment.

Excel may store a run's color in the cell's base font and omit a redundant run override. The independent reader resolves that inheritance; a regression fixture covers it. The live edit was dispatched once, initially reported uncertain by the incomplete reader, then reconciled through a fresh read after the verifier correction. It was not replayed.

## Native comments and existing hyperlinks
`node live/comments.mjs preview ALIAS --drive DRIVE --item ITEM --file JSON` prepares up to 200 native comments. Each item supplies `sheet`, `cell`, `expectedValue` and `text`; existing comments are refused. Apply with the returned `--plan`, `--hash` and `--execute`; use `verify` after uncertainty. Saved comment text and anchors are independently checked from a downloaded workbook. Historical authorship must be stated in comment text, not impersonated as the new comment author.

The hyperlink adapter is experimental and general link editing is disabled. A live synthetic test established that assigning a destination can replace the displayed rich text. Its narrowly bounded recovery payload requires an empty cell, missing link, exact prior label and font; it independently checks the saved destination. Do not use it to update links in reviewed cells. Neither adapter adds worksheets or uploads a replacement workbook.

## Bounded presentation and reference edits
`node live/layout.mjs preview ALIAS --drive DRIVE --item ITEM --file JSON` supports explicit sheet order/tab colors, frozen top-left extents, finite range formatting, exact-range unmerge, row autofit, existing table styles/striping and literal text-cell updates. A `freeze` value of `B2` freezes the first two rows and columns. The payload has `sheets`, `ranges`, `tables` and `cells` arrays; unknown properties, formulas as text targets, stale cells and unsupported hosts refuse. Apply with the stored plan/hash and `--execute`; reconcile uncertain writes with `verify`. It does not rename sheets or evaluate arbitrary JavaScript. A table specification may include `removeColumns` (exact column names) or `removeRows` (zero-based data-row indexes), with row and column removal kept separate for each table. The full native table is part of the stale-preview check. Operations refuse neighboring populated cells that would shift, whole-table removal and out-of-range targets. Review dependencies before removing a field; saved verification checks unrelated formulas and content, and does not constitute a preflight dependency analysis. Native tests covered isolated column and row removal; an initial fixture with neighboring cells established the shift behavior now refused. Download verification checks all cell values/formulas, rich text, comments, table definitions, merges and hyperlinks; range appearance still needs native visual acceptance. Excel may change table differential-style IDs when a style changes, so those style identifiers are excluded from table-schema comparison.

`node live/references.mjs preview ALIAS --drive DRIVE --item ITEM --file JSON` repairs up to 200 references without flattening displayed text. Each item supplies `sheet`, `cell`, exact `before`, `oldAddress`, `newAddress` and `replacements` pairs for URLs embedded in text. Address changes must remain within the same HTTPS origin. Apply/verify use stored plans and single-dispatch receipts. The adapter reads current runs for stale-format checks, assigns the link with explicit display text, then restores complete effective fonts derived from the retained downloaded baseline. Aggregate range-font values are not a safe base for mixed runs: Excel can report the first run’s strikethrough for the entire cell. Explicit false values are retained for the other runs. Read-return metadata and null aggregate font values are never sent to setters. A disposable live test verified saved rich colors and the changed destination; independent verification compares effective character formatting, formulas, tables, comments and other cells. A failed intermediate mutation can still flatten a target, so never replay an uncertain write: inspect its saved state and retained baseline first.

These commands close the owned coauthoring session before independent saved-file checks. A native save acknowledgment can precede persistence; later read-only verification may reconcile an initial mismatch without another edit. Tests and private consumer checks do not certify other tenants, platforms or all document features.

If a dispatched reference operation changed only formatting, `preview ALIAS --restore-plan ORIGINAL_UUID` can prepare a separate bounded font-restoration operation. It verifies the already-intended text and destinations, derives fonts from that operation’s original saved baseline, and skips hyperlink assignment. The new apply has its own hash and dispatch receipt; it is not a replay of the link mutation. Independent verification compares against the original intended result. Unknown theme/indexed font colors and unsupported font properties refuse rather than guessing. A later coauthor change still requires reconciliation.

An explicit XLSX run-font element resets omitted boolean font toggles to off; only a run without that element inherits the complete cell font. The saved-reference reader and baseline derivation handle this distinction. The regression checks both equivalent serialization and a real introduced strike. Layout previews hash each finite range’s values/formulas instead of returning their full contents through the bridge; full downloaded preservation checks remain unchanged.

For portable evidence citations, reference items may set `citation: true` with `newAddress: null`. This removes the selected existing hyperlink with `RemoveHyperlinks`, permits exact literal text replacements and restores the saved effective character fonts. It does not retarget a link or touch formulas. Saved verification requires the hyperlink to be absent and checks the intended text, character formatting and all other cells.

Table layout specifications may also use `renameColumns` with exact `before`/`after` names. Duplicate, missing and colliding headers refuse; the full native table is checked for staleness, and the saved header/table schema is checked. Dependent queries must be updated by the caller.
