## Interface inventory and save guarantees — 2026-11-23
Rechecked from public vendor sources only; no tenant, account or browser was contacted.

- **Time Tracking REST v7.** The [REST directory](https://community.workday.com/sites/default/files/file-hosting/restapi/index.html)'s specification dated 2026-11-21 offers `POST /workers/{ID}/workerTimeBlock`, `PATCH` and `DELETE` on a block, `GET /workerTimeBlocks` by worker and date range, `GET /workers/{ID}/timeTotals`, `GET /workers/{ID}/period`, the worker's time zone and eligible time-entry codes, and time clock events. Access is secured by the "Process: Time Block REST APIs" domain with the Time Tracking scope, through an API client registered in the tenant. v7 requires `inTimeWithTimeZone` and `outTimeWithTimeZone` objects carrying an IANA zone and an offset date-time, and rejects the older flat fields.
- **The REST read is not a complete week.** `GET /workerTimeBlocks` states that it does not return incomplete time blocks, time off or overtime-request blocks. A complete read would have to combine time blocks with time clock events and absence data under further scopes, and whether that covers every state still needs proof on a real tenant. The read contract's rule stands: anything the adapter cannot verify fails the read.
- **No documented save precondition.** The v7 specification has no ETag, `If-Match` or other precondition on any time-block write, and no idempotency key. It documents a critical validation (A758) refusing in/out times that conflict with existing entries, which guards one time slot but not other changes to the week, and nothing comparable is documented for quantity-only blocks. A time block's `status` is a separate field; submission goes through other operations, but whether a created block is always left unsubmitted has not been verified.
- **Agent-Ready MCP.** [Agent-Ready MCP tools](https://developer.workday.com/doc/GUID-949559e7-10c3-438a-abb2-e452c23d9da8-enHYPHENus.md) authenticate only with OAuth 2.1 and PKCE through an Agent System User token obtained when an administrator registers the agent definition in the Agent System of Record; in delegate mode the agent never exceeds the acting user's permissions. Setup and discovery still require Extend Professional access, as recorded below.
- **Sana from Workday.** Claude's connector directory lists an official Workday connector, published from [Workday/everywhere](https://github.com/Workday/everywhere/tree/main/plugins/sana) under Apache-2.0. It is a beta service that tenant administrators apply for; it needs an active Workday subscription agreement and agents configured in the tenant's Agent Management Hub, and its MCP address is supplied per tenant. It relays natural-language requests to Workday's own agents, so it offers neither deterministic time-block operations nor conditional saves. It suits reading or one-off requests through a Claude client rather than this standalone adapter.
- **Import Reported Time Blocks.** This SOAP web service batches blocks into asynchronous jobs for bulk loads and treats times without an offset as US Pacific. It is an administrator integration, not a per-worker draft route.

Consequences for this capability: every documented API or MCP route needs a client or agent that the tenant's administrators register and grant. The selected account's own client list and task search, recorded privately on 2026-11-02, showed no such grant and no self-service registration. That is an access gate, not proof of tenant denial. Separately, no documented Workday interface offers the revision precondition `create_draft(..., expected_revision=...)` requires, so writes stay blocked on every route unless the save guarantee itself is redefined by an explicit decision and then proved on real, separately authorized work. The [active spike](../../docs/active-spikes/workday-capabilities.md#transport-proof-and-dispositions--2026-11-23) holds the proposed dispositions.

## Existing-session browser reader
Chrome documents [user-approved connections to an existing session](https://developer.chrome.com/blog/chrome-devtools-mcp-debug-your-browser-session) from version 144. The user turns on remote debugging at `chrome://inspect/#remote-debugging`, Chrome asks the user to Allow each connection, and it shows an automation banner while one is active. This does not restart the browser, copy its profile or use the older command-line switches. The grant permits broad browser control, so working only in its own tab is the reader's boundary, not a narrower browser permission. Chrome must stay open; this is not unattended or headless operation.

[scripts/workday_browser.py](../scripts/workday_browser.py) reads one week through [scripts/chrome_session.py](../scripts/chrome_session.py), a DevTools client built on the Python standard library. It reads the port from Chrome's `DevToolsActivePort` file, as Playwright's documented channel discovery does, and waits for the user's approval. It lists tab addresses only to find the browser profile that has the configured tenant open, never printing them, then opens its own background tab in that profile, attaches to that tab alone and closes it afterwards.

On 2026-11-23 Playwright 1.63's `connect_over_cdp("chrome")` timed out against the user's everyday Chrome 157 even after the user clicked Allow. A minimal connection to the same browser was approved and answered within a second, and the browser also listed internal browser-UI targets. Playwright attaches to every target in the browser and appears to stall on some of them; the reader avoids that, and with it any access to the user's other tabs.

The reader takes the week from the Enter My Time calendar, Review Time by Week and each block's read-only details, and cross-checks them: the worker's instance ID on the page, the calendar's and review's block IDs, times and types, the time-zone label on every block against the confirmed one, per-day and weekly totals, and the period-end markers that fix each day's pay period. It refuses on any disagreement, unknown entry kind, meal or break out reason, worktag, sign-in page or layout change, and writes nothing to Workday. Observed behaviour it depends on:

- Workday's time-zone text, such as "GMT-06:00 Central Time (Chicago)", is the zone's fixed label and appears even on daylight-time dates, so it is matched against the user-confirmed IANA zone and never parsed as an offset.
- A "Time Period End" marker gives the ending period's start and end; a week without one lies inside a single period.
- Review Time by Week drops its In, Out and Out Reason columns for an empty week.
- Details repeat each label for screen readers, and a background tab can run adjacent texts together, so the reader takes text from individual elements and text nodes rather than rendered lines.
- Block approval status comes from the calendar's appointment style; only `approved` has been seen, so every other style reads as unknown, which `use-workday` treats as protected.

Live proof, 2026-11-23, with the user's approval at each connection: a complete approved week read exactly, with its pay-period boundary, classification and totals, and the snapshot validated through `use-workday read-timesheet`. An empty week also read correctly. Writes, the entry dialog and the permitted time-type list remain unread; an empty week takes its time types from the account file's user-confirmed list.

## Fixed adapter contract before enabling execution
The implementation currently supplies only `workday_core.save_draft` and the private Unix journal. A production setup-owned adapter must implement `read(target)` and `create_draft(target, entry, expected_revision=...)`, with `supports_conditional_create = True` only after proving the actual service precondition. A local flag or fake test is not evidence. Plain preflight reads cannot close the race between read and write; a browser route without an equivalent guarded save cannot satisfy this executor. Do not silently remove that protection to make a demonstration work.

`read` must independently bind tenant, worker, exact Monday-start week and timezone, return complete normalized records and all service statuses, permitted types/worktags, payroll periods, service totals, revision and save semantics. Fail on unknown layout, session expiry, MFA, missing pages, ambiguous controls, warning/validation banners or inability to verify any field. Do not turn missing UI text into an empty week. The adapter must validate worktag IDs and required combinations; the offline schema only validates string structure. Readback must be authoritative after each save, not an optimistic client form value.

`create_draft` must save exactly one planned block with explicit breaks and classifications, atomically refuse a changed revision and never certify, check in/out or submit. It must not internally retry after a lost response. Any transport error after invocation is conservatively uncertain. No arbitrary scripts/endpoints/selectors are part of the public interface. Submit, delete, edit and approval operations are absent.

Use one shared private journal directory for all clients using this integration. `Journal.guard` locks by complete target/week; different private directories would bypass local serialization. The service revision guard must still protect against other clients and human edits. Journals contain private entry data and must stay outside version control or inside an ignored private destination with mode 0700; files use 0600. Intent is flushed before mutation and retained on an uncertain effect. Interrupted processes release the OS lock but retain the intent.

Before adding a live resume/reconciliation command, establish a supported way to determine that an outstanding save has settled. Under the same lock, inspect the durable intent and perform fresh authoritative reads, verify target/status/content and distinguish saved, absent, conflicting and still-unknown outcomes. An immediate absence after timeout is not proof that a remote request will never finish. Unknown outcomes remain blocked. A settled reconciliation must record evidence privately before retiring the intent and generating a new reviewed plan. No recovery command or automatic journal deletion is exposed today. Partial saves do not authorize deleting records as rollback.
