# Runtime files and cleanup
This inventory covers the Microsoft provider, Word/PowerPoint browser runtime, Google Docs image repair and GitHub collaboration recovery used during installation reconciliation. Real runtime files are private and untracked. Authored `docs/scratch/` notes, test procedures and synthetic fixtures are tracked documentation; they are not runtime scratch.

| Owner / files | Current location and selection | Purpose and removal boundary |
| --- | --- | --- |
| Google Docs image exports and repair records | Explicit `images --out-dir` or `replace-images --record` in an owner-only directory outside Git; no default output inside the checkout | Exported images and operation records use mode 0600. The record and adjacent mode-0700 `.images` directory retain source hashes, target metadata, available preimages and dispatched/verified/cleanup outcomes. Updates are atomic and flushed before dispatch; preserve unresolved records. Delete completed originals only when recovery/evidence is no longer needed. Signed content URLs are omitted. The remote temporary import is trashed only by its recorded ID; an interrupted upload or failed cleanup needs explicit recovery. |
| Microsoft `.env`, account configuration and MSAL cache | `~/.agent-hands/microsoft/config/` by default, or explicit paths described in [account access](../setup-microsoft-services/references/account-access.md); `.env.example` is tracked, real values are ignored | Account selection, credentials and refresh state. Do not print or commit them, reset them to repair an unrelated runtime, or expire them as temp files. |
| Graph PowerShell authentication | The SDK's existing user authentication store | Reusable delegated sign-in. Separate from PowerShell's regenerable startup/module caches; changing a startup cache does not renew or revoke sign-in. |
| Microsoft request/response files and PowerShell startup/module cache | Owner-only per-process directories under the OS temporary root, selected through `TMPDIR` or platform discovery; checkout paths are refused | Removed by the owning process on normal completion or handled termination. Registered run directories older than 24 hours are eligible for guarded cleanup on each new run or `authorize cleanup-temp --execute`; preview with `authorize cleanup-temp`. Cleanup requires the same owner, directory identity and a confirmed-absent controller. Live/reused PIDs, denied liveness, symlinks and unregistered directories are skipped. Hard termination can leave plaintext until a later cleanup trigger; no scheduled worker runs. No routine dump retention. |
| Word account, owned browser profile, add-in manifest/certificate/settings, plans and dispatch receipts | Designated external `agent-hands/office/ALIAS/` user-state root; `~/.agent-hands/office/ALIAS/` on every platform. `AGENT_HANDS_STATE_DIR` overrides the private base. Legacy `.word-state/ALIAS/` requires explicit whole-account migration; [setup and recovery](../setup-microsoft-services/references/word-browser.md) | Browser sign-in, add-in identity, target-bound previews and no-replay recovery. Cookies stay in the owned profile; manifests do not contain them. Treat the whole account directory as sensitive. Preserve unresolved receipts and the shared lock. No arbitrary personal-profile adoption. Explicit retention preview/execution can retire old plan content under the rules below; credentials and unresolved receipts never expire this way. |
| PowerPoint plans and receipts | `powerpoint/` beneath that same account directory | Shares the owned browser and lock with Word. Migrate the whole account together; do not create separate writable copies of its journals. |
| Word and PowerPoint cloud-verification downloads | Owner-only per-run system temp directories outside checkouts | DOCX/PPTX bytes used for independent verification, removed in `finally` after success or failure. Registered crash-left readbacks older than 24 hours are eligible for guarded cleanup on next readback or explicit `word-browser cleanup-temp`; only confirmed-dead controllers qualify. Historical unregistered folders are skipped. This is not a scheduled service or encryption; abrupt termination can leave private bytes until cleanup. They are not retained evidence by default. |
| Planner audit and recovery | `M365_PLANNER_AUDIT_LOG` selects the audit file (default `~/.agent-hands/microsoft/planner/task-writes.jsonl`); `planner-task-chat/` and `planner-task-delete/` are beside it | Private operation metadata, message/content fingerprints and task/deletion receipts. Preserve unresolved outcomes. A complete successful readback distinguishes completed records from pending writes; changing the audit path also changes the recovery location, so coordinate every writer before relocation. |
| Microsoft Files / mail / Excel audits and write recovery | Defaults beneath `~/.agent-hands/microsoft/{files,mail,excel}/`, with organization/draft stores beside their capability audit; provider-owned audit overrides retain their documented selection | Can identify private resources or intended edits without containing tokens. Recovery journals must survive interrupted or uncertain writes. Do not treat an audit-path change as a harmless log rotation. |
| GitHub collaboration journal and lock | Default `~/.agent-hands/github/HOST_OWNER_REPO/`, shared across checkouts/worktrees; explicit `--state-dir` selects a different root | Actor/repository/target metadata, intended steps and verified or uncertain outcomes. Move the complete journal only with writers stopped and all callers selecting the same new location. Never discard unresolved records or remove a lock merely because its file exists; the lock is held by the OS. |
| Earlier experimental readbacks, screenshots, exports and settings | Historical experiments may mix these in an ignored `state/` folder | Classify by writer and recovery use before disposal. A downloaded synthetic fixture can be disposable while an adjacent dispatch receipt or secret is required state. Retire obsolete experiment secrets with the experiment after confirming maintained tools do not reference them. |

For new persistent stores, select an explicit private user-state directory outside the checkout and document its override and migration behavior. Office and Microsoft state use the external root with explicit migration and noncredential legacy routing markers. GitHub defaults use the same root; existing checkout journals require the [explicit local migration](../setup-github/references/collaboration.md), while custom selections remain unchanged. Prefer outside-checkout audit/state overrides when configuring a new installation, preserving one shared recovery location per account or project.

Keep useful expected results and sanitized fixtures with the owning tests. Retain a real-run original only for an explicit evidence need, in a designated private location with its purpose and removal condition. Do not publish browser storage, private manifests, actual account configuration, raw service responses or unsanitized diagnostics. Git ignores and redaction checks are complementary; neither establishes that an old retained file is safe to delete.

## Retention and encryption
Office plan content has a bounded explicit retention command: unused previews are eligible after seven days, independently cloud-verified plans after thirty days. Receipts survive removal, and uncertain or merely save-returned operations remain protected. See [retention commands](../setup-microsoft-services/references/word-browser.md#office-plan-content-retention). No persistent records are silently aged out. Microsoft and GitHub audit/receipt formats do not yet have a common safe terminal-state retirement procedure; retain them until that owner-specific procedure exists or a separately reviewed account/project retirement resolves them.

Additional application encryption is deferred. Private owner-only directories/files prevent access by other ordinary OS users; they do not protect against other processes running as the same user or an unlocked compromised account. A future credential-manager integration does not automatically encrypt document text or operation metadata.

## Additional provider stores and publication recovery
These owners use explicit, separately verified storage contracts. Their settings migrations preserve existing sign-ins, overrides and recovery rather than copying selected credentials or treating journals as disposable.

| Writer | Actual selection and lifecycle / remaining work |
| --- | --- |
| Google configuration, OAuth client files and token JSON | `~/.agent-hands/google/config/`, or existing explicit Google overrides. The explicit settings migration includes relative OAuth files and the default Gmail audit. Token publication remains owner-only and atomic with normal cleanup; credentials and unresolved audit state do not expire. |
| GitHub setup configuration | `~/.agent-hands/github-settings/config/`, or existing explicit GitHub overrides. gh still owns authentication. Configuration, collaboration journals and export publication recovery have distinct stores. |
| Canvas configuration and renewal recovery | `~/.agent-hands/canvas/config/`, or existing Canvas env-file/config-directory selection. Renewal locks, pending and last-result files move with settings under their existing OS locks. Pending renewal remains protected recovery. |
| Slack and Trello configuration | `~/.agent-hands/{slack,trello}/config/`, or existing explicit env/config selection. Complete credential-bearing settings move without changing account identity; no generic expiration applies. |
| Odoo configuration and request pacing | `~/.agent-hands/odoo/config/`, or existing Odoo overrides. Relative pacing state moves with settings. Requests/responses use registered owner-private `odoo-work.*` system-temp directories, removed on normal/handled exit. Registered crash-left runs older than 24 hours have preview/explicit cleanup requiring separate deletion consent; no automatic historical cleanup runs. |
| Workday account binding, saved browser profile, snapshots and save journal | `~/.agent-hands/workday/config/account.json`, `~/.agent-hands/workday/journal/`, where the user chose the saved profile `~/.agent-hands/workday/chrome-profile/` with its lock and `sign-in.json`, and, while a session runs, `~/.agent-hands/workday/session.sock`, or the same paths beneath `AGENT_HANDS_STATE_DIR`, owner-only; snapshots only where `--out` names them, owner-only and outside Git checkouts | The confirmed tenant, worker instance ID, time zone, Workday's label for it and the user's browser and save-safeguard choices. Snapshots hold the user's actual hours; the journal holds a timestamped intent per uncertain save or submission and its per-week lock. The saved profile holds a Workday sign-in that only its own Chrome reads and writes, so treat the whole folder as a credential: never copy, share or commit it, and remove it only at the user's request, with no session running. `sign-in.json` holds only times: when it was signed in, last worked and was first found signed out. Nothing else here is a credential, and with the everyday Chrome the sign-in stays in the user's own profile. An outstanding intent blocks further saves to that week until `reconcile` settles it; nothing expires automatically. The session socket is owner-only, exists only while its process holds the Chrome connection, and is removed when the session ends; a leftover socket with no listener is replaced on the next start. |
| Penpot board-replacement journal | `~/.agent-hands/penpot/replacements/FILE_ID/`, or the same path beneath `AGENT_HANDS_STATE_DIR`, with one OS lock per file shared by every caller. Each record holds the plan, the replaced boards' complete old shapes, the locked version's ID and the stage history; records contain private design content. Dispatched, uncertain and mismatched records block another replacement of the same board until `board_journal.py reconcile` settles them or the user accepts the outcome. There is no expiry or deletion command; retiring records needs separate approval. |
| GitHub export publication | `~/.agent-hands/github-exports/RUN/` contains durable artifact hashes, new exports and old-output backups for an explicit output destination. Interrupted publication supports read-only inspection/reconciliation and guarded restoration of missing targets. Completed/restored/retrieval-failed runs become eligible after seven days, with an absent controller and separate exact-run deletion consent. Unresolved runs never expire. Legacy `.github-export.*` directories are inventoried without automatic migration, restoration or deletion. |
