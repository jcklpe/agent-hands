# Runtime files and cleanup
This inventory covers the Microsoft provider, Word/PowerPoint browser runtime, Google Docs image repair and GitHub collaboration recovery used during installation reconciliation. Real runtime files are private and untracked. Authored `docs/scratch/` notes, test procedures and synthetic fixtures are tracked documentation; they are not runtime scratch.

| Owner / files | Current location and selection | Purpose and removal boundary |
| --- | --- | --- |
| Google Docs image exports and repair records | Explicit `images --out-dir` or `replace-images --record` in an owner-only directory outside Git; no default output inside the checkout | Exported images and operation records use mode 0600. The record and adjacent mode-0700 `.images` directory retain source hashes, target metadata, available preimages and dispatched/verified/cleanup outcomes. Updates are atomic and flushed before dispatch; preserve unresolved records. Delete completed originals only when recovery/evidence is no longer needed. Signed content URLs are omitted. The remote temporary import is trashed only by its recorded ID; an interrupted upload or failed cleanup needs explicit recovery. |
| Microsoft `.env`, account configuration and MSAL cache | Setup-owned defaults and explicit paths described in [account access](../setup-microsoft-services/references/account-access.md); `.env.example` is tracked, real values are ignored | Account selection, credentials and refresh state. Do not print or commit them, reset them to repair an unrelated runtime, or expire them as temp files. |
| Graph PowerShell authentication | The SDK's existing user authentication store | Reusable delegated sign-in. Separate from PowerShell's regenerable startup/module caches; changing a startup cache does not renew or revoke sign-in. |
| Microsoft request/response files and PowerShell startup/module cache | Owner-only per-process directories under the OS temporary root, selected through `TMPDIR` or platform discovery; checkout paths are refused | Removed by the owning process on normal completion or handled termination. Hard termination can leave a run directory; confirm its owner has stopped before removing that exact directory. No routine dump retention. |
| Word account, owned browser profile, add-in manifest/certificate/settings, plans and dispatch receipts | Designated external `agent-hands/office/ALIAS/` user-state root; `~/.agent-hands/office/ALIAS/` on every platform. `AGENT_HANDS_STATE_DIR` overrides the private base. Legacy `.word-state/ALIAS/` requires explicit whole-account migration; [setup and recovery](../setup-microsoft-services/references/word-browser.md) | Browser sign-in, add-in identity, target-bound previews and no-replay recovery. Cookies stay in the owned profile; manifests do not contain them. Treat the whole account directory as sensitive. Preserve unresolved receipts and the shared lock. No arbitrary personal-profile adoption or automated age-based cleanup. |
| PowerPoint plans and receipts | `powerpoint/` beneath that same account directory | Shares the owned browser and lock with Word. Migrate the whole account together; do not create separate writable copies of its journals. |
| Word and PowerPoint cloud-verification downloads | Owner-only per-run system temp directories outside checkouts | DOCX/PPTX bytes used for independent verification, removed in `finally` after success or failure. Registered crash-left readbacks older than 24 hours are eligible for guarded cleanup on next readback or explicit `word-browser cleanup-temp`; only confirmed-dead controllers qualify. Historical unregistered folders are skipped. This is not a scheduled service or encryption; abrupt termination can leave private bytes until cleanup. They are not retained evidence by default. |
| Planner audit and recovery | `M365_PLANNER_AUDIT_LOG` selects the audit file (default ignored `use-planner/task-writes.jsonl`); `planner-task-chat/` and `planner-task-delete/` are beside it | Private operation metadata, message/content fingerprints and task/deletion receipts. Preserve unresolved outcomes. A complete successful readback distinguishes completed records from pending writes; changing the audit path also changes the recovery location, so coordinate every writer before relocation. |
| Microsoft Files / mail / Excel audits and write recovery | Provider-owned overrides `M365_FILES_AUDIT_LOG`, `M365_MAIL_AUDIT_LOG`, `M365_EXCEL_AUDIT_LOG`; see each capability's setup/use contract | Can identify private resources or intended edits without containing tokens. Recovery journals must survive interrupted or uncertain writes. Do not treat an audit-path change as a harmless log rotation. |
| GitHub collaboration journal and lock | Default `.github/project-collaboration/` in the resolved primary worktree; explicit absolute `--state-dir` supports private storage elsewhere | Actor/repository/target metadata, intended steps and verified or uncertain outcomes. Move the complete journal only with writers stopped and all callers selecting the same new location. Never discard unresolved records or remove a lock merely because its file exists; the lock is held by the OS. |
| Earlier experimental readbacks, screenshots, exports and settings | Historical experiments may mix these in an ignored `state/` folder | Classify by writer and recovery use before disposal. A downloaded synthetic fixture can be disposable while an adjacent dispatch receipt or secret is required state. Retire obsolete experiment secrets with the experiment after confirming maintained tools do not reference them. |

For new persistent stores, select an explicit private user-state directory outside the checkout and document its override and migration behavior. Office state now uses the external root with explicit migration and noncredential legacy tombstones. Other listed legacy defaults remain actual behavior until their separately tested migration replaces them; this inventory does not silently relocate them. Prefer outside-checkout audit/state overrides when configuring a new installation, preserving one shared recovery location per account or project.

Keep useful expected results and sanitized fixtures with the owning tests. Retain a real-run original only for an explicit evidence need, in a designated private location with its purpose and removal condition. Do not publish browser storage, private manifests, actual account configuration, raw service responses or unsanitized diagnostics. Git ignores and redaction checks are complementary; neither establishes that an old retained file is safe to delete.
